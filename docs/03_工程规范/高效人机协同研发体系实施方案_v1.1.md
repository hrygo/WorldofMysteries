## 1. v1.0 → v1.1 修订对照

| 主题 | v1.0（HACF 2.0） | v1.1（HACF 2.1） |
|:---|:---|:---|
| 工作区环境 | 软链共享主仓 `engine/.venv`，「零秒就绪」 | 每工作区 `uv sync --locked --extra dev` 独立环境，共享 uv 全局缓存 |
| 运行时隔离 | 表述为「完全杜绝文件锁冲突」 | `git worktree` 只隔离源码；`.hacf/workspace.json` 租约隔离 TMPDIR / SPM scratch / 测试库 / socket / 端口段 |
| 上下文切片 | 固定压到 `< 500 Tokens` | 最小**充分**上下文：`context.core_manifest` + `max_core_tokens` + `slice_strategy`，不足可申请扩权扩上下文并出新修订版 |
| 验收命令 | 胶囊携带 `verification_commands` | 胶囊只引用 `gates.profile` + `gates.profile_digest`，命令固化于 `.hacf/gates/*.json` |
| 禁区 | `forbidden_patterns` 写入但无判定 | `forbidden` 真实拦截；`contracts/`、`.hacf/`、`.github/`、`migrations/` 需仲裁扩权 |
| 验收产物 | 向胶囊回写 `attestation` + 状态跃迁 | 契约不可变；产出独立 `Work Receipt` / `Integration Receipt` |
| 摘要口径 | 「sha256 机器防伪签名」 | 「可复算内容摘要凭单」；抗伪造由受保护分支 + CODEOWNERS + CI 复算承担 |
| 集成竞态 | 声称「集成管道强制 rebase 并重跑门禁」 | `expected_main_sha` + 合入前 compare-and-swap 复核 + 合入后 post-merge smoke（rebase 需人工/后续任务触发） |
| PR 报告 | 硬编码「✅ PASSED」卡片 | 只复述凭单事实；门禁权威结论归属 CI required checks |
| 协议归属 | `task_capsule` 作为第 28 个产品 Schema | 研发编排协议独立于 `contracts/engineering/`，产品领域契约保持 27 + 1（IPC） |

## 2. 协同作业四步（SOP）

```bash
# 1) 任务切片：生成不可变契约（含受保护门禁引用与焦点切片）
python3 scripts/agent_capsule.py pack \
    --role AGT-DATA --task-id M2-DATA-KERNEL \
    --title "四库 SQLite 数据内核迁移与连接池实现" \
    --focus "database,outbox,migration"

# 2) 开启隔离工作区（独立 .venv + 资源租约）
python3 scripts/collab_pipeline.py start \
    --branch feat/m2-data-kernel --role AGT-DATA --task-id M2-DATA-KERNEL

# 3) 本地门禁（可指定角色档案；默认 FULL_P0）
bash scripts/gate_runner.sh            # 在工作区内执行
bash scripts/gate_runner.sh DOMAIN_P0  # 角色专精档案

# 4) 范围裁决 + 生成 Work Receipt（绝不回写胶囊）
python3 scripts/agent_capsule.py verify \
    --capsule .agents/capsules/M2-DATA-KERNEL.json --cwd "$(pwd)"

# 5) 集成：门禁 → CAS 合入 → post-merge smoke → Integration Receipt
python3 scripts/collab_pipeline.py integrate --branch feat/m2-data-kernel --auto-clean
```

**扩权场景**（非 AGT-ARB 角色需要触碰高风险面）：

```bash
python3 scripts/agent_capsule.py pack \
    --role AGT-DATA --task-id M2-SCHEMA-EVENT --title "扩权：新增 domain_event 字段" \
    --grant-privileged "contracts/schemas/domain_event.schema.json" \
    --risk-class high
```

扩权记录写入胶囊 `scope.privileged_grants`，随 PR 进入 CODEOWNERS 评审，并在凭单中留下 `privileged_uses` 痕迹。

## 3. 关键机制

### 3.1 门禁主权与摘要链

```text
capsule.gates.profile_digest
        ==  .hacf/gates/registry.json（目标分支权威）中的 sha256
        ==  sha256(.hacf/gates/<profile>.json 文件字节)
```

任一环不匹配：本地拒绝执行，CI 拒绝合入。改写门禁档案必须由 `AGT-ARB` 执行
`python3 scripts/gate_profile.py refresh-registry` 并走架构评审。

### 3.2 契约与凭证分离

```text
.agents/capsules/<TASK_ID>.json                 # 不可变契约（不回写）
.agents/receipts/<TASK_ID>/<head_sha>.json      # Work Receipt（本地门禁结果）
.agents/receipts/<TASK_ID>/<head_sha>-integration.json  # Integration Receipt（唯一可授权合入）
```

rebase 会改变 commit SHA，旧凭单自动失效 —— 这是**特性**而非缺陷：合入凭证必须对应最终提交。

### 3.3 覆盖缺口可见化

门禁档案的 stage 可声明 `expects`（期望存在的测试资产）与 `empty_selection_policy`。
未落地的用例面不会静默通过，而是记录为 `passed_with_gap` 并入凭单 `coverage_gaps`，在 PR 卡片中显式呈现。

### 3.4 资源命名空间租约

`.hacf/workspace.json` 为每个工作区分配：`tmpdir` / `spm_scratch` / `test_db_dir` / `ipc_socket` / `log_dir` / `port_range`。
门禁执行器自动注入这些变量（`swift test --scratch-path ${WOM_SPM_SCRATCH}`）。

## 4. 双层防御矩阵（v1.1）

| 层级 | 位置 | 职责 |
|:---|:---|:---|
| 本地 L1 | `scripts/gate_runner.sh` + `agent_capsule.py verify` | 角色档案门禁、范围裁决、签发 Work Receipt |
| 本地 L2 | `scripts/collab_pipeline.py integrate` | CAS 合入、post-merge smoke、签发 Integration Receipt |
| 云端 C1 | `capsule-audit.yml` → `scripts/capsule_audit.py` | 边界裁决、门禁档案主权、凭单证据完整性（无证据不放行） |
| 云端 C2 | `ci.yml` | 三阶段权威门禁（架构适应度 / Pytest / Swift 6），`--locked` + `uv lock --check` |
| 云端 C3 | `pr-gate-reporter.yml` | 只读证据摘要卡片（不宣称测试结论） |

## 5. 已知局限与后续项

1. **CAS 拒绝分支未在真实并发下演练**：main 在门禁与合入之间前进时本地拒绝合入的逻辑已就绪，
   但尚未在多 Agent 真实竞态中复现；建议 M1/M2 落地时用两个并发工作区演练一次。
2. **Integration Receipt 的签名强度**：当前为摘要 + 受保护分支评审；
   若后续需要跨机器/跨仓库信任，再评估 in-toto/DSSE 正式签名（Sigstore），不提前引入供应链签名成本。
3. **`stale_context` 判定粒度**：基于目标分支 SHA 变化；尚未覆盖「目标分支多次前进」的累积情形与自动 re-pack。
4. **风险自适应门禁**：已按角色落地档案，但尚未按 diff 规模/路径动态升级 profile（如仅改注释也跑全量 Swift 打包）。
5. **语义冲突预测**：胶囊已具备 `dependencies.depends_on / conflicts_with` 字段，
   调度器侧的 capsule overlap analysis 与 single-writer 协调通道尚未实现。
