# Golden 001 验收追溯记录

> 核对时间：2026-09-27  
> 范围：`docs/06_实施基线/2026-09-26_Golden_Five_Turn_Iteration_Plan.md` §4 检查点 A/B/C 与 §6 总完成条件  
> 结论：**发现并修复一处追溯性缺陷**；修复后 §6 全部条目有可验证证据

## 1. 审计发现：追踪矩阵是愿望清单

计划 T1 要求交付「G001–G012 与八个故障点的追踪矩阵及测试入口；**未实现部分明确失败，不以 skip 计为通过**」。

核对 `engine/tests/test_golden_runtime_spec.py` 发现该要求**未被满足**：

- 矩阵把 G001–G012 映射到 12 个测试名、8 个检查点映射到 8 个测试名，**共 20 个名字无一真实存在**（`git grep "def <name>"` 全部落空）。
- 矩阵测试 `test_runtime_trace_matrix_targets_every_assertion_and_failure_checkpoint` 只断言「名字以 `test_` 开头」且「互不重复」，**从不断言测试存在**。

后果：即使把这些测试全部删除，矩阵测试依然全绿。**它提供的是虚假保证，而非追溯性** —— 恰好是计划明令禁止的「以 skip 计为通过」。

同时核对行为覆盖，发现两条断言**完全无任何测试**：

| 断言 | 规则 | 原状态 |
|---|---|---|
| G002 | `character_must_not_identify_morris_as_culprit` | 无覆盖（全仓库无 morris/culprit 断言） |
| G006 | `closure_must_not_add_major_conflict` | 无覆盖（第五轮 expected 连 `active_conflicts` 字段都没有） |

## 2. 修复

### 2.1 补写缺失断言（G002 / G006，另加固 G007 / G008）

新增三个运行期测试于 `engine/tests/test_golden_five_turn_application.py`，断言基于实测运行值而非假设：

- `test_character_never_identifies_morris_as_the_culprit` —— 五轮提交后扫描全部 `turn_knowledge_changes` 与 `turn_world_events`，断言无任何 `morris`/`culprit` 归罪，且 world event 类型只能是 `evidence_observed`/`evidence_recovered`（取证而非指控）。素材要点：随包 `fact.family_suspects_morris` 是**怀疑**，运行期唯一知识变更是 `jonathan_left_occult_note`，怀疑未被提升为事实。
- `test_closure_turn_adds_no_major_conflict` —— 断言 `active_conflicts` 全程恒为种子基线 `["find_jonathan"]`，closure 解决运行而不制造升级。
- `test_hidden_truth_never_enters_public_world_writeback` —— 断言全部 world event `visibility.public is False` 且 `known_by` 非空，并复核 `secret_04` 终态仍为 `hidden`。

并在 `test_finalization_requires_five_committed_turns_and_replays_idempotently` 中补 G007 运行期断言：落库 Episode 的 `unresolved_threads` 非空（关闭运行不等于解开谜团）。

### 2.2 矩阵改为真实 node ID 并加入存在性守卫

矩阵值全部改为 pytest node ID（`tests/<file>.py::<test>[<param>]`），并新增两个参数化测试：

- `test_every_assertion_maps_to_a_test_that_exists[G001..G012]`
- `test_every_failure_checkpoint_maps_to_a_test_that_exists[8 个检查点]`

它们读取目标测试源文件，断言 `def <name>(` 确实存在；故障检查点额外断言参数化 id 字符串存在。**目标缺失即 FAIL，不 skip。**

唯一性约束已放宽并注明原因：G003/G005 由同一测试同时钉住（序列 9 与 turn4 reinterpret 同属一个 fixture 断言）；CP2/CP3 在磁盘上不可区分，共用一个参数化用例（解释已落盘、回合未提交）。

### 2.3 变异验证

守卫不是纸面约定，已做两次变异确认其真的会失败：

| 变异 | 结果 |
|---|---|
| G002 指向 `..._MUTANT`（不存在的测试名） | `AssertionError: G002 points at a missing test` |
| CP8 指向 `[cp8_MUTANT_missing_id]`（不存在的参数化 id） | `AssertionError: ... points at a missing parametrization id` |

两次变异均已恢复。
