## 1. 叙事模型选型

| 项 | 值 | 来源 |
| --- | --- | --- |
| 网关 | CLIProxyAPI `http://127.0.0.1:8317/v1` | 运维配置 |
| 模型 ID | `opencode-go-qwen38-flash` | `/v1/models` 实测在列 |
| provider id | `cliproxyapi-opencode-go` | `WOM_MODEL_PROVIDER_ID` |
| 思考 | **默认开启**，不得关闭 | 见 §1.2 |

### 1.1 延迟实测（N=10，2026-09-29）

| 配置 | 契约通过 | 延迟区间 |
| --- | --- | --- |
| 思考开（默认） | 10/10 | 3.7s – 8.5s |
| 思考关 | 10/10 | 1.5s – 2.4s |

两组都跑同一提示词（简单问答）与同一结构化契约（`narrative`/`speaker`，`narrative` 带 `minLength: 1`），均要求返回可解析 JSON。

### 1.2 修正：先前记录的「关思考 4~5/10」不成立

先前结论记为「开思考 10/10、关思考 4~5/10，故不得关闭思考」。2026-09-29 用上述两种提示词各复算 N=10，**关思考同样是 10/10**，未复现失败。

因此**不得关闭思考**这条规则继续成立，但依据换成实测可支持的那一条：

- 关闭思考后延迟降到 1.5–2.4s，但叙事质量明显退化——开启组紧扣「医生停顿」这一线索，关闭组退化为「先把这杯茶喝了」一类通用台词；
- 契约通过率两者相同，说明先前的失败并非来自结构化输出本身。

**未归因项（如实列出）**：先前那组 4~5/10 的原始请求体与提示词未留存，无法判定是路径不同、上游行为变化，还是当时测量本身有误。在补齐可复现的原始请求之前，该数字不得再作为验收依据引用。

### 1.3 `minLength: 1` 不由 provider 执行

该 provider 不落实 JSON Schema 的 `minLength` 约束，不能指望约束解码兜底。运行时兜底在
`engine/ai/live_turn_workers.py` 的 `missing_character_speech`（两处）：模型返回空台词时按失败处理，
而不是把空字符串当作合法叙事提交。

## 2. 超时层级

三个数字必须自上而下严格递减，否则内层超时永远等不到触发，传输层会先报一个指不明的阶段超时。

| 层 | 值 | 代码位置 |
| --- | --- | --- |
| 客户端耐心上限 | 180s | `EngineIPCClient.defaultRequestTimeout` |
| 引擎阶段预算 | 45s | `AuthorizedExecutionBudget.timeout_seconds` |
| 模型 HTTP 超时 | 30s（上限 600s） | `engine/ai/openai_compatible.py` 的 `_DEFAULT_TIMEOUT_SECONDS` |

30s < 45s < 180s，层级成立。客户端这一层是**耐心上限而非延迟预算**：快回复立即返回，慢路径不再被客户端在半路丢弃。

修复前的生产客户端上限为 5s，早于引擎最坏预算（3 次串行调用 + 提交 + 语音），必然掐断回合——这是已确认并已修复的真实缺陷，不是理论风险。

## 3. 客户端活性（已由真实回合证明）

真实语音回合实测，客户端观察到的状态序列（连续两次运行一致）：

```
not_required|pending|pending  →  not_required|running|pending  →  not_required|ready|ready
```

关键点：提交 ACK 自身**不携带**交付结果（`submit_delivery_state = absent`）。
因此上表证明的是客户端确实轮询并观察到了状态迁移，而不是碰巧读到一次已完成的快照。
测试同时断言序列首项为进行中、末项为终态，因此「只读到一次已完成快照」的实现同样会失败。

轮询参数：间隔 1.0s、上限 90s、终态即停、`blocked` / `unavailable` 视为终态。
上限取自实测：提交后叙事与音频就绪耗时 11.3s – 22.1s，90s 留有充分余量且不会无限轮询。

## 4. 诚实边界

1. **token 级流式不可达**。模型输出在 COMMIT 之前已完整取得，提交前把未提交文本显示给玩家会直接违反不变量 9（提交即命运）。本轮交付的是「活性 + 分段渐进呈现 + 音频就绪即播」，**不是** token 流式，不作此包装。
2. **渐进呈现是表现层行为**。契约规定 `narrative_segments` 在 `pending` / `running` 时必须为空，因此客户端逐段揭示的是权威快照的前缀，并永远收敛到权威快照本身，不改写内容。
3. **未归因失败**：§1.2 的 4~5/10 未能复现，原始请求未留存。
4. **未跑的真实服务测试**：无。真实回合（麦克风 → SpeechRail ASR → 引擎提交 → 后台叙事与音频 → 媒体套接字 → 扬声器）已实跑通过；`FLASH-03A~03C` 的门禁为离线门禁，不包含真实服务调用。

## 5. 本轮真实回合同时证明的四件事

| 验收项 | 证据 |
| --- | --- |
| 领域提交不重复 | 提交 ACK 无交付、后台 worker 续跑，`commits` 计数与崩溃恢复断言一致 |
| 重启后必要产物可恢复 | 崩溃注入下 App 自动重启 Engine 并让 durable worker 续跑，终态收敛且不新增提交 |
| 音频失败不影响文字 | 每个 sealed unit 只尝试一次，失败如实上报，文字链路不受影响 |
| 隐藏知识不进入模型 | 由受控上下文断言保证，隐藏知识只进入领域存储，不进入推理输入 |
