# 价值目标与验收基准（FLASH）

> 用途：交付方自证与用户验收的**唯一口径**。任一条不成立，整体即不通过。
> 基线：`main` @ `cba478c`｜日期：2026-09-29｜前序：AO-01~AO-06 已合入

## 一、模型

叙事模型经 CLIProxyAPI（`cliproxyapi-opencode-go` / `opencode-go-qwen38-flash`），选型以 N=10 实测矩阵为据、可复算。**默认不得关闭思考**：关闭后延迟降至 1.5~2.4s，但叙事质量明显退化。先前记为「关思考 4~5/10」的数字 2026-09-29 复算未复现（两种提示词均 10/10），不再作验收依据，原始请求未留存。该 provider 不执行 `minLength:1`，须运行时兜底（`engine/ai/live_turn_workers.py`），不指望约束解码。

## 二、超时

修复真实缺陷：原生产客户端 5 秒上限早于引擎最坏预算（3 次串行调用 + 提交 + 语音），必然掐断回合。现为**耐心上限而非延迟预算**：客户端 5s→180s；引擎内模型超时 30s 严格小于阶段预算 45s。快回复立即返回，慢路径不再被丢弃。

## 三、流式交付

修复真实缺陷：提交后叙事与音频由后台异步产出，客户端原本只读一次，`pending|running → ready` 永不可见、需手动刷新。现以有界轮询（间隔 1.0s、上限 90s，终态即停）真正观察到该转换；叙事按 segment 渐进呈现（表现层揭示快照前缀，永远收敛到权威快照，**非** token 流式）；音频就绪即播并与文本重叠。全程只读已提交投影，不变量 9 不削弱。

## 四、可复算

真实端到端回合证明：领域提交不重复、重启后必要产物可恢复、音频失败不影响文字、隐藏知识不进入模型。

## 五、诚实边界

token 级流式在提交前不可达，不包装为已交付；重试参数取自实测时长分布，不靠估计；未归因失败与未跑的真实服务测试一律列明。

## 验收方式

逐条对照上述五条，附 `FULL_P0` 四阶段门禁证据与各包 Work Receipt；**缺证据即不通过**。数据与边界见 [`09_FLASH_选型与边界固化.md`](09_FLASH_选型与边界固化.md)。
