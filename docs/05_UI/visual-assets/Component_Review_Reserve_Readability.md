# 组件审查：灵性读数与操作可读性

## 对世界体验的直接影响

本批审查对象是已有的灵性仪表、状态条与紧凑操作；不增加玩法、修改 Canon 或重新生成已批准原画。

原生渲染暴露了三类不能用“已使用 Token”掩盖的问题：

- 灵性仪表把渐变随半圆一起旋转，导致高存量指针进入红区、低存量反而靠近蓝区。
- 非有限输入可能触发整数转换错误，或被伪装成完整/枯竭读数；未知不能替代真实世界状态。
- 主按钮在禁用、非活跃窗口和按下状态下多次透明度合成，文字可能不可辨；不可用不等于不可读。

## 修正

1. 仪表直接绘制上半圆，左端为零、右端为满量程；危险/预警/存量区复用现有 `Gauge.criticalThreshold` 和 `warningThreshold`，不再旋转已着色的图形。黄铜外框、尺寸和指针造型保留。
2. `WOMMetricReading` 区分有效零值和不可用值；无效输入不显示指针、不标危险或安全状态。状态条在临界时使用警示色，装饰渐变不能覆盖警示。
3. 共用的按钮状态配色由 `WOMButtonPalette` 解析；禁用主按钮改为中性背景与清晰文字，非活跃主按钮保留不透明暗金/墨色配对。禁用时清除悬停反馈，焦点环不参与布局。
4. 标准动作符号经过目标平台存在性验证；语音按钮不再用局部前景色覆盖共享状态规则。

## 已知边界

这里的阈值是已有视觉刻度，输入来自调用方；此批不产生灵性值、不计算角色能力，也不宣称演示数值已接通领域引擎。

无效值为 `NaN` / 正负无穷时显示“读数不可用”；有限越界值保留既有归一化裁切行为。零值是有效、明确的读数。

此前临时分支 `595acca3…` 的配色/无效值修复被保留并接续，本批额外修正其渲染仍存在的仪表色带倒置。不能把该临时分支的通过结果自动算作 PR 当前 head 的验收。

## 验证方式

- `ControlStateReviewTests`：实际生产配色解析器的 640 种状态/底色组合，以及禁用稳定性与原生符号存在性。
- `MetricReadingReviewTests`：非有限输入、有限边界、阈值、临界状态覆盖装饰渐变。
- `GaugeScaleReviewTests`：原生 SwiftUI 像素采样，检查低/中/高刻度真实颜色和未知状态不暗示安全或危险。
- 原生复核图：0%、10%、50%、85%、100%、未知读数；输入栏用 AppKit 宿主检查，不能用缺少原生输入内容的快照替代。

测试和截图记录绑定实际验证的 commit/tree。全组件 Token 审查、键盘遍历、VoiceOver 与所有真实业务页面验收仍需分批完成，不作“全系统通过”声明。

## API 依据

Apple `Path.addArc(center:radius:startAngle:endAngle:clockwise:transform:)` 文档说明角度从正 x 轴计量，最终方向受 SwiftUI 翻转坐标系影响。该行为以生产组件的像素测试交叉验证，而非只比对源码文本。
