# 组件审查：人物权衡时保持安静

审查基线：`48ea46101a02b27b715f43a46559c8d378fc137b`，接续 PR #39 组件轨道。

## 对世界体验的影响

[交互运行态基线](../Interaction_Runtime_State_v1.0.md) 第 3、10 节要求：人物权衡时保持人物/场景，不使用加载转圈，不伪造回应；聆听环在空闲时暗淡、聆听时呼吸、决策时安静。

此前组件却在空闲阶段持续呼吸，在 deciding 阶段循环旋转，并把所有 speaking 状态写成“克莱恩正在回应”。这些不是 Token 命名问题，而是让界面错误表达了世界正在发生什么。

## 本批修正

- 安静状态不再持有旋转角度、波纹相位或永久动画状态。只在 listening 且没有有效正音量时创建呼吸动画；切换状态即移除该动画分支。
- 已有有效音量只影响 listening / speaking 的幅度。无效音量不会生成非有限几何；没有音量数据时不伪造播放波形。
- Reduce Motion、禁用、非活跃窗口下保留状态文字，停止几何动态。操作回调继续由调用方提供，组件不创建领域状态或计时器。
- 回应文案默认不包含人名。可选 `speakerName` 只消费调用方已知的当前发声者；未知、空白或其他状态不会借用某个默认角色。
- 保留双同心圆黄铜造型、既有尺寸/色彩/字体/动作 Token；不新增世界设定或 IPC 契约。

## 验收与限制

`ListeningRingReviewTests` 覆盖静态/聆听/播放、有限与非有限音量、三类动态限制、角色名称、状态切换以及原生静态图像一致性。旧 source guard 同步校验真实动画分支，不再要求过时的状态启动函数。

渲染与 protected gate 的结果必须绑定实际验证 SHA；测试通过不代替完整 App 的键盘/VoiceOver 和语音后端端到端验收。UI 仍只表达调用方发布的状态，不能因环已亮起就宣称录音、人物决策或 Domain COMMIT 已完成。

本批不接管已批准的场景/物品原画，不声称全组件 Token 审查已完成。
