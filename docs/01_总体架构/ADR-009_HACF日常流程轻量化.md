# ADR-009：HACF 日常流程轻量化

> 状态：Accepted（用户授权本地实施；远端生效须经 PR）
> 日期：2026-10-03
> 范围：研发流程、PR 审计、贡献入口；不改变产品契约、世界数据或运行服务。
> 部分取代：[ADR-004](ADR-004_协同层门禁主权与凭证分离_v1.0.md) 的日常强制任务凭证与角色范围裁决。

## 判断与依据

HACF 的质量检查和工作区隔离有实际价值，但现有强制协作流程的边际收益不足以支持继续普遍使用。选择简化日常流程，保留真正检查产品行为的门禁。

在 `bc4792ca` 核验：

- Git 跟踪 374 份胶囊、581 份 JSON 凭单，合计 4,436,597 字节；六个协作脚本共 3,494 行。
- 最近 14 次主线合入中，胶囊和凭单增删 4,659 行，产品代码及测试增删 1,430 行，其他流程及文档增删 1,105 行。逐次统计，14 次的凭证增删行数均超过产品代码与测试。PR 标题虽多为 `chore(evidence)`，仍包含实质改动，不能误称为“纯凭单 PR”。
- 最近 30 次 Capsule Audit 运行均成功；其中含连续纠正故事书事实判断的提交。该检查证明流程可满足，不证明功能接线正确。
- 历史修复包括多胶囊并集、治理通道自锁、`target_ref`、短套接字路径和 Git 环境隔离。前两类是流程自生复杂度；后两类隔离措施仍有保留价值。

以上是负担代理指标与案例，不能据此推算工时、缺陷避免数量或因果收益。没有前后对照实验；“净收益不足”是基于这些证据和当前单人项目形态作出的工程判断。

## 日常决策

1. 一项用户功能可以在同一分支跨目录完成。任务角色用于说明专长，不构成额外的人类授权，也不强迫按目录拆任务。
2. 日常流程为理解目标与风险 → 分支开发 → 按改动面验证 → PR → CI 与评审 → 合入后按需回收。无需 `pack`、Work Receipt、Integration Receipt 或本地 `integrate` 预演。
3. `capsule_audit.py` 默认 `lightweight`：只检查门禁档案与 registry 一致性，明确产品测试结论来自 CI；不读历史胶囊、不扫描凭单，不将旧角色范围作为阻断条件。
4. 保留 `Capsule Gate` 名称作为分支保护兼容接口，其职责改为轻量门禁配置校验。`All Quality Gates Passed` 继续执行架构、契约、Python、Swift 与 Xcode 检查；原有按变更面分类保持不变。
5. PR 凭单报告仅在人工添加 `hacf-evidence` 标签后触发，日常 PR 不再自动发表重复报告。PR 描述只需问题、结果、验证、实际风险。
6. 用户数据保护、15 条产品不变量、产品模块依赖边界、跨语言契约一致性和高风险变更影响分析保持有效。授权来自用户；质量结论来自测试、构建和评审。
7. 并行写入或主工作区不干净时使用独立 worktree、独立环境与短路径运行资源；单人普通任务不强制建立隔离环境。回收前验证干净和内容落地，不能强删未知改动。

## 可选治理与迁移

Schema、角色默认值和协作脚本保留供显式治理使用。用户于 2026-10-03 进一步授权清理不再需要的历史胶囊数据：旧胶囊与关联凭单从当前树移除，追溯通过 Git 历史与校验归档完成；当前树仅需保留活跃任务数据。特殊多执行者任务可以显式使用旧 SOP，并用 `capsule_audit.py --mode governed` 审计；该模式只选本次变更携带的胶囊，缺少胶囊时拒绝，不再回退扫描整个历史目录。

旧规范仅在显式治理模式内适用。当前入口为本 ADR、根 `AGENTS.md`、`CONTRIBUTING.md` 与 `wom-collaborator`；历史资料的“每次必须”不能恢复日常强制流程。

## 实施与验收计划

由当前主代理在独立分支串行实施，不触碰主工作区的 cherry-pick 或已有未跟踪文件。

- 新建 `engine/tests/test_hacf_lightweight.py`：跨域且无胶囊可通过；旧损坏胶囊不被读取；档案损坏、缺失、registry 非法或为空均失败；显式治理仍拒绝无胶囊；未知模式、无效 Git 基线失败；CLI 默认行为与库接口一致。
- 修改 `scripts/capsule_audit.py`：新增轻量审计和模式选择，保留显式治理算法，去除历史胶囊回退；不得用成功提示冒充产品验收。`project_status.py dispatch` 默认输出轻量步骤，文本和 JSON 均不派发旧胶囊命令；仅 `--governed` 显式展示旧步骤。
- 同步 `.github/workflows/capsule-audit.yml`、`pr-gate-reporter.yml`、PR 模板、required-check 描述，以及有效文档和技能入口；不改检查名、不修改远端 ruleset。
- 先运行新增测试确认失败，再实施并运行新增测试及已有治理回归，最后运行 `FULL_P0`。检查实际 stage 输出、未执行项和文档链接，不仅看退出码。

验证命令：

```bash
cd engine
uv run --locked --extra dev pytest -q tests/test_hacf_lightweight.py tests/test_hacf_governance.py
cd ..
python3 scripts/capsule_audit.py --base-ref origin/main
python3 scripts/gate_profile.py check
python3 scripts/check_required_checks.py
bash scripts/gate_runner.sh FULL_P0
```

## 风险与回退

取消的是 Agent 声明的目录授权审计，意味着 CI 不再替人判断任务授权范围；实际目录变更由 diff 评审、用户授权和产品边界测试共同判断。本地档案摘要仅证明一致性，不宣称能防止 PR 同时改写档案与 registry；此类更改须评审，治理路径仍触发全量 CI。

远端分支保护不变；在本分支经 PR 合入前，线上仍使用旧流程。回退可恢复 CI 的 `--mode governed`、自动报告触发与旧贡献入口；历史任务凭证可从清理前提交 `8b836ca3` 或校验归档恢复。不能通过删除 required check 或只给它固定成功结果来“简化”。

后续观察任务到功能交付的耗时、真实阻断的回归、流程返工次数；仅在收益有证据时追加机制。

## 本地核验（2026-10-03）

- 新增行为与既有治理回归：137 passed。新增审计与派发测试均先验证旧行为失败，再验证修改后通过。
- `FULL_P0`：架构、Python 全套、Swift 测试、Xcode App 构建四阶段全部通过。
- 必需检查名称契约、轻量 CLI、新增相对文档链接和差异空白检查通过。
- `capsule_audit.py` 的既有 19 项风格诊断未增加；新增测试与派发脚本的风格检查通过。
- 图谱覆盖核验发现相关文件已变更，结论以当前源文件与运行结果为准，未重建索引。
- 远端 CI、PR 合入和简化后的交付耗时尚未验证；本地门禁通过不替代这些证据。
