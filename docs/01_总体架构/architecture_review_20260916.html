WorldSession 深模块：将浅信封调度收缩为单一响应式叙事流

涉及文件: macos-app/WorldOfMysteries/AppState.swift · EngineIPCClient.swift · IPCEnvelope.swift

当前摩擦与浅接缝 (Problem)

当前 AppState 直接面对多个浅模块：processManager.startEngine()、ipcClient.connect()、ipcClient.performHandshake()，以及动态信封编解码。UI 必须手动编排多步骤状态机；一旦增加断线重连、心跳恢复或流式音频调度，AppState 将产生严重复杂度泄漏（无 Locality），在 UI 视图与网络通讯之间来回弹跳。

深模块演进方案 (Solution)

引入 深模块 WorldSession，对外暴露极限精简的 interface： func sendAdvice(_ text: String) async throws -> AsyncStream<NarrativeTurn> 在接缝（seam）之后深度内聚：进程自愈拉起、Unix Socket 双向通道、心跳监听、重连退避、强类型 DTO 泛型折叠。UI 仅需一行代码接入叙事流。

杠杆率与删除测试 (Leverage & Deletion Test)

Deletion Test: 删除 AppState 中零散的进程与 Socket 控制代码，并没有将逻辑搬迁，而是将其彻底收敛入 WorldSession 深模块。

Testability: 视图层单元测试只需注入 MockWorldSession，实现毫秒级 UI 测试，彻底摆脱多进程真实依赖。

ContextCompiler 深模块：多路召回与语义授权硬核内聚

涉及文件: engine/application/context_compiler.py · memory_engine.py · lore_engine.py

当前摩擦与浅接缝 (Problem)

若在编排器 SessionOrchestrator 中逐步串联“语义授权校验”、“图谱关系检索”、“向量召回”、“多路排序”和“Token 预算打包”，将导致编排器成为膨胀的胶水代码（Lack of Locality），并且微小模块之间的依赖会导致不变量 6（零知识越界）在多处存在漏防漏洞。

深模块演进方案 (Solution)

将 ContextCompiler 塑造成绝对深模块。仅暴露单一不可妥协接口： compile_authorized_context(character_id, world_time, observation) -> ContextPacket 在接缝后彻底锁死语义硬门禁（Hard Boundary）、四库检索路由与 Token 动态裁切，调用方无从触碰未授权的 Canon 隐藏知识。

杠杆率与删除测试 (Leverage & Deletion Test)

Leverage: 编排层仅用一次无参感知调用，撬动背后多数据库并发查询、重排序算法与动态预算算法。

Security: 授权过滤在检索发生之前就物理生效，彻底杜绝大模型“越界幻觉召回”。

AgentCapsule 深任务胶囊：消除多角色交接中的上下文稀释

涉及文件: .agents/prompts/ · docs/03_工程规范/HANDOFF_CHECKLIST.md · scripts/gate_runner.sh

当前摩擦与浅接缝 (Problem)

当前定义了 7 个 Markdown 角色提示词与一份人工交接清单（HANDOFF_CHECKLIST.md）。当 Arbiter 将任务派发给 Domain Agent 时，需要人类在不同文件与分支状态间反复横跳，手动拼接 Git diff、测试命令与图谱符号。这种“纯文本浅接缝”导致极高的人工摩擦，且极易因疏忽发生 Context Dilution（上下文稀释）或漏测。

深模块演进方案 (Solution)

构建 深任务胶囊脚手架 scripts/agent_capsule.py。接口极其简明： rtk python3 scripts/agent_capsule.py pack --role AGT-DOM --task M2-DataKernel 在接缝背后自动：提取分支 git 状态、调用 codebase-memory-mcp 定位目标符号与上游调用链、动态拼接最小必要上下文、并内嵌针对该角色的专精测试断言。

杠杆率与删除测试 (Leverage & Deletion Test)

Locality: 角色指令、代码拓扑切片、执行边界与后置门禁完全内聚为一个单一可交付“胶囊”。

AI-Navigability: Agent 仅需阅读 1 个自动生成的任务胶囊即可开始精准工作，避免大模型因全量扫描无用文档导致 Token 爆炸。

CollabWorktree 事务级并行工作区：无锁流水线化集成

涉及文件: scripts/worktree_manager.sh · scripts/gate_runner.sh · .github/PULL_REQUEST_TEMPLATE.md

当前摩擦与浅接缝 (Problem)

现存的 worktree_manager.sh 只是 git worktree add/remove 的极薄封装（Shallow wrapper）。多 Agent 在并行分支完成代码后，仍需手工切换目录、手工跑 gate_runner.sh、探测 main 分支冲突并手工清理目录。在多人/多 Agent 并发场景下，任何中间步骤的疏漏都会导致未测试代码合入。

深模块演进方案 (Solution)

将工作区分支生命周期升级为事务性深管道 scripts/collab_pipeline.py： rtk python3 scripts/collab_pipeline.py integrate --branch feat/data-kernel --auto-clean 将“工作区隔离”、“跨语言三阶段门禁自动化跑批”、“Rebase 冲突探测”、“架构适应度核验”及“原子合流与自愈清理”一体化封装。

杠杆率与删除测试 (Leverage & Deletion Test)

Leverage: 一行命令完成从分支代码交付到主分支洁净合入的全流程，杜绝脏状态污染。

Locality: 门禁检验与分支清理强绑定，任何测试失败直接回滚该 Worktree，保证 main 分支的绝对不变量。
