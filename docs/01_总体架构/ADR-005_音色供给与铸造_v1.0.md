## 1. 背景与证据边界

持久声音身份由三个条件共同成立：角色绑定稳定、provider 制品可锁定、该制品在目标合成条件下通过验收。目录发现、参考注册、机器检查、人工听审、发布与正式合成分别产生不同事实，彼此不替代。

2026-09-28 的本仓静态复核确认以下基线：

| 证据 | 当前结论 | 对终态方案的约束 |
|:---|:---|:---|
| `engine/domain/voice_identity.py` | `VoiceBindingScope` 包含 owner、world、worldline、presentation identity、phase、locale；`conditional_pin` 依据内容寻址与撤销状态产生 | 复用完整作用域；内容寻址不承担听感质量证明 |
| `engine/infrastructure/voice_binding_resolver.py` | resolver 接收指定 `voice_id`，按主角构造 scope，检查声音修订、assurance、模型来源与目录修订；冲突时拒绝 | 扩展为逐说话者解析，保留严格 pin 与冲突拒绝 |
| `engine/application/voice_casting.py` | `VoiceCastingService` 先持久保留，再激活；显式替换使用修订约束 | 供给结果经过既有耐久屏障，不直接触发首块音频 |
| `engine/infrastructure/migrations/003_world_voice_bindings.sql` | 表现绑定保存在 `world.db`，不推进世界事实 revision | 新字段通过后续迁移加入，已执行的 003 迁移保持不变 |
| Voice-First 技术设计 §8、§12 | 热路径使用已验收声音；首次绑定先落库；换声显式；最终回退为字幕 | 缺货不借用其他角色声线，不阻塞领域 Commit |

SpeechRail 的音色创建—使用指导方案记录 F1–F7 与 C1，证据类型为源码和契约核查，明确不等于目标机故障实测。本次只复核该记录，不据此宣称缺陷仍存在或已经修复。上游准入以第 6 节的行为验收为依据。

本次没有服务调用、凭证读取、模型操作、真实目录盘点或音频听审。外部官方页面检索没有返回可核实正文，因此内置音色数量、自定义创建 API 是否存在及第三方验收细节均不作为本 ADR 的事实前提。

## 2. 决策

### D1 · 供给控制面与叙事表达面分离

Voice Foundry 是 Engine application 层的供给编排器。Context Compiler 输出经过语义授权的声音需求；Foundry 消费需求、查目录、组织候选、等待听审并接收发布结果。provider adapter 负责版本化协议映射，领域层不依赖 SpeechRail SDK、HTTP 或 SQLite。

```text
语义授权 → VoiceCastRequest → 查找满足准入条件的目录音色
                                  ├─ 命中 → 保留 / 激活绑定
                                  └─ 缺货 → 预览 → 选优 → 注册候选
                                                        ↓
                                 参考确认 → 跨文本复验 → 人工听审 → 发布
                                                                            ↓
                                                        严格核验 → 保留 / 激活绑定

领域 Commit → 已授权表达计划 → 按说话者读取绑定 → 严格合成 → 音频 / 字幕
```

创建与质量检查在准备期或场景边界的后台队列执行，不位于互动首音频的等待链。Commit 后出现缺货时，表达层记录供给需求并继续字幕交付；创建失败、取消、超时均不回滚领域事实。创建操作本身不违反不变量 9，反向影响已提交事实才构成违例。

### D2 · 来源、引用稳定性与发布资格正交

音色来源记录为设计、授权克隆、导入或 provider 内置；来源不直接决定准入。角色对白与旁白的生产绑定同时满足：

1. 用途和语言获得授权，provider 接受该用途。
2. 声音制品具有不可变修订，支持正式合成时的条件锁定。
3. 目标执行模型及其制品修订可解析、可锁定、可在回执中核对。
4. 参考检查、输出复验、人工身份与自然度听审具备匹配当前验收范围的有效证据。
5. 音色处于允许当前用途的发布状态，且未撤销。

SpeechRail 报告 `legacy` 且 `voice_revision=null` 的系统音色不满足第 2 条，仅用于独立的 UI 提示或诊断，不进入角色及旁白绑定。具备全部条件的设计、克隆或导入音色使用同一准入规则；不以 `forged` 标签代替核验，也不永久排斥具备相同保证的其他 provider 来源。

持久身份保存公开声音画像、参考制品和验收证据。逐句 `instructions` 只表达 provider 实际支持的临时表演，不能把一个无锁定保证的系统音色变成稳定角色身份。主要人物使用通过验收的专用声音或明确批准的复用声音，具体人物设定由内容管线提供，不硬编码进领域核心。

### D3 · 绑定、制品与验收证据分别版本化

| 对象 | 权威方 | 含义与变化规则 |
|:---|:---|:---|
| `persona_revision` | 游戏侧 | 可公开声音画像的修订；不携带隐藏真身 |
| `binding_revision` | 游戏侧 | 完整 scope 到声音及证据引用的版本；使用 CAS 演进 |
| `voice_revision` | provider | 不可变声音制品版本；别名变化不改变已绑定引用 |
| `execution_model_id` / 模型制品修订 | provider | 实际执行身份；与目录集合修订分开记录 |
| `identity_evidence` | provider 保存验收原始记录，游戏保存引用与核验快照 | 在明确条件下完成的机器检查与人工听审，不由游戏评分伪造 |

证据范围至少包括 provider 实例、voice revision、实际模型/制品修订、合成 variant、locale、验证策略版本及影响身份的处理配置指纹。证据保存 reference/output 维度结果、测试文本和音频摘要、人工审听对象与结论、创建时间及失效/撤销信息。正式计划引用不可变 `evidence_id` 与摘要，不复制参考录音或完整私有报告。

设计声音的“身份合格”指符合获准画像并保持跨文本连续性，不要求像某个真实人物。克隆声音另有授权参考与相似度评价。相似度、可懂度、自然度和人工身份判断分别记录，单一分数不等于发布通过。

执行模型、声音制品或验收相关配置变化，使原证据不适用于新范围；同一旧范围的历史证据仍保留。目录增加无关音色不自动使所有质量证据失效，但既有目录 pin 仍按协议执行，旧 pin 被拒绝时重新核验而不静默替换。

### D4 · 多候选预览与正式铸造分离

预览具有任务 ID、候选 ID、参数指纹和音频摘要，尚不具有可绑定的生产声音身份。固定 seed 是可复现输入，不保证跨模型、跨设备或不同版本得到相同声音。

候选数按预算配置，首版上限为 4；并发度依据 provider 调度能力，默认串行。预览、验证与互动语音共享资源时，互动请求优先，后台任务接受背压、取消和截止时间。预览同样消耗推理与存储预算，不预设“廉价”或“零持久化”。

自动初筛检查质量和获准画像，提供同场声音相近提示；机器评分不代替选优及最终人工听审。选中候选保存确切的参考资产摘要与生成配方。provider 能导入该预览时，正式候选引用同一资产；只能重新生成时，重新生成的参考重新确认，旧试听不能证明新参考合格。

### D5 · 首次绑定与显式换声分别处理

绑定键使用 `owner_id + world_id + worldline_id + presentation_identity + phase + locale`，不只使用 `presentation_identity`。provider 实例作为制品引用的一部分参与核验，跨实例相同 `voice_id` 不视为同一音色。

已有绑定是选角硬约束。目录排序、场景差异、角色升格或新音色发布均不自动改写它。首次绑定由 Engine Writer 事务保留并激活，只有持久化胜出的 binding revision 授权输出。并发请求复用该胜者，CAS 冲突不覆盖现有绑定。

显式换声由用户命令携带预期 binding revision，结果只作用于未来的句或场景边界。世界线分叉继承分叉点可见版本，不继承之后的变更。历史 take 保留原绑定、声音、模型及证据引用。

### D6 · 缺货、不可用与安全拒绝分别表达

`no_authorized_voice_candidate` 映射为类型化供给结果，不再单独决定领域回合是否成功。结果至少区分 `ready`、`supply_required`、`pending_review`、`provider_unavailable`、`policy_blocked`；鉴权失败、用途不符和能力缺失不触发无限铸造。

已提交回合的文本和表达音频使用独立状态。声音未就绪时，界面显示“文字已就绪 / 音色准备中”或具体阻塞原因，供给任务可以继续；不把已提交回合伪装成未提交或整体失败。

| 情况 | 表达行为 |
|:---|:---|
| 同一 take 有有效且允许播放的缓存 | 播放原缓存并保留原证据 |
| 当前绑定有效，临时合成失败 | 有界重试同一绑定；可用时采用中性同身份表演 |
| 存在显式批准且适用于当前场景的备用表达 | 使用批准的备用；旁白转述只使用已审核模板并明确说话者 |
| 首次出现且没有合格绑定，或所有许可回退均不可用 | 交付字幕，标记语音待准备或不可用 |
| 声音或许可被撤销 | 停止该范围的新合成；历史缓存按撤销策略决定能否播放 |

新角色不借用主角声线，不用其他角色声线冒充“同身份”。首次音色就绪后在未来边界开始使用，不自动重播已经读过的字幕；用户显式重播使用单独的新 take。

### D7 · 内容期备齐与场景预热共用准入链

内容期覆盖旁白和首批 3–5 个主要人物，完整经过候选、验收、发布和绑定演练。进入语音体验前的预检报告各身份是否就绪；缺失项显式呈现，不以“目录恒定非空”作为假设。

场景预热仅使用当前已获准呈现的信息，不读取隐藏未来剧情。偶发人物按同一链路准备，人工听审未完成时保持待审并按 D6 交付。用户未审听不产生自动通过结论，系统不为缩短等待降低发布标准。

### D8 · 语义授权贯穿所有出站与持久化边界

`VoiceCastRequest` 包含 schema version、任务关联 ID、完整绑定 scope、persona revision、用途、locale、公开声音特征、批准的测试文本及预算。role/phase 是获准的表现阶段，不从隐藏真身推导。

Context Compiler 判定信息是否可公开；schema 限制字段、长度与枚举；application/Domain validator 核对 scope、阶段与授权来源；adapter 只发送允许的字段。schema 本身不能识别自然语言里夹带的剧透，不能代替语义授权。

角色隐藏关系、未揭露身份、剧情未来不进入提示词、候选命名、音频元数据、错误详情或日志。向 provider 发送 opaque 关联 ID 与声音需求，不发送无关的完整世界状态。预览文案、人工听审材料和诊断信息执行同一规则。

### D9 · 状态机、幂等与恢复形成闭环

游戏侧任务状态与 provider 音色生命周期分别建模：

```text
任务：requested → previewing → awaiting_selection → provisioning
     → validating → awaiting_review → published → binding → ready
分支：failed / cancelled；可恢复等待携带 retry_after 与最后确认阶段
音色：candidate → reference_validated → synthesis_tested
     → identity_accepted → published → deprecated / revoked
```

`published` 只表示 provider 发布成功，`ready` 表示游戏侧当前 scope 已持久绑定并满足生产准入。界面可用动作来自已协商的 provider 状态，不假设任意失败终态支持 resume。

每个有副作用的操作持久保存 request ID、provider candidate/voice ID、幂等键、冻结 payload 指纹和最后确认结果。相同键与相同 payload 重放收敛到同一对象；不同 payload 拒绝。网络超时或结果未知时先查询，再以原 ID、原键和原 payload 恢复，不创建替身任务绕过未知结果。

发布成功而绑定失败时，任务保留已发布制品并重试核验/绑定，不重复铸造。两个任务竞争同一 scope 时，只有 CAS 胜者激活；未选制品不自动删除，可保留供其他已授权需求复用。取消阻止后续游戏侧绑定，不虚构撤销已完成的 provider 发布；迟到结果记录后等待明确处置。

`deprecated` 禁止新 scope 绑定，既有绑定在许可、证据和服务支持仍有效时继续使用。`revoked` 禁止新合成；撤销原因单独确定历史音频能否播放。二者都不隐式换声，也不删除审计事实。

### D10 · 权威持久化与运行索引分开

| 数据 | 位置与权威 |
|:---|:---|
| 声音制品、参考资产、发布与原始验收记录 | provider 的持久存储 |
| 声音画像、binding revision、证据引用、用户换声命令 | `world.db` 表现元数据 |
| 需要跨重启恢复的供给意图、幂等映射、选优结果与最后确认阶段 | `world.db` 独立表现任务表，经 Engine Writer 写入 |
| 任务队列索引、租约、轮询进度、诊断和临时统计 | `runtime.db`；从任务和 provider 状态重建 |
| 试听/输出音频 | `assets/`，按摘要引用，受保留与容量策略控制 |

上述表现写入使用独立修订，不推进 `world_meta.revision`，不伪造 WorldEvent，不写 `canon.db`。表名和字段由后续产品 schema 与迁移统一定义。`runtime.db` 删除后不丢失唯一幂等键、人工选优结果或不可恢复的用户意图。

游戏数据库与 provider 之间不建立跨库原子事务，采用持久意图、幂等调用和结果对账恢复。App 通过类型化 IPC 操作任务与绑定，不直连数据库或绕过 Engine 调用发布端点。

### D11 · 契约和运行接线保持单一事实源

产品 schema 包含 `voice_cast_request`、`voice_foundry_state` 与独立的 `voice_identity_evidence` 引用结构；相关 Python/Swift 模型由统一契约生成或校验。`PerformancePlan` 和 SpeechUnit 保存可追溯的绑定及证据引用，provider 私有报告留在 adapter 边界。

`VoicePreviewPort` 负责预览与候选资产获取；`VoiceDesignPort` 负责创建、查询、参考确认、验证、提交真实人工评审和发布。端口位于 application 边界，实现位于 infrastructure；实际 HTTP 路径、字段和错误由经协商的 provider 契约映射，不把内部接口名直接当成公开 API。

运行时逐说话者解析完整 scope，`StoryRuntimeConfig.voice_id` / App `--voice-id` 不再作为产品的全局角色选角来源。旧配置只能进入显式迁移流程，不能为多个角色批量绑定同一声音，也不能绕过新准入。

目录发现属于路由提示，`available=true` 不等于生产验收通过。冷态 `production_ready=false` 若仅表示模型未加载，可发起严格请求让服务准备并最终裁决；证据缺失、范围不符或撤销仍在首块音频之前拒绝。实际合成回执与已锁定的 voice/model/evidence 范围一致后，输出才进入交付链。

## 3. 未采纳项与取舍

| 方案 | 决策依据 |
|:---|:---|
| 无条件限定只有游戏铸造的 `forged` 来源合法 | 来源不能证明质量或引用稳定性；准入依赖正交证据 |
| 固定 seed 或 instruction 直接充当身份 | 输入相同不等于制品、执行模型和听感均相同 |
| 缺货时使用主角声线 | 破坏角色区分与身份连续性；字幕是确定可行的终点 |
| 缺证据时沿用旧规则放行 | 灰度和回退不能绕过生产闸门 |
| 全部供给状态只放 `runtime.db` | 丢失持久意图和幂等映射后不能安全恢复 |
| 所有任务等待 SpeechRail 全部 App 缺陷修复 | 契约和 fake 验证可独立完成；产品准入由实际使用链的证据决定 |
| 默认并行四路以解决延迟 | 并行可能挤占互动资源；调度以能力与测量为准 |
| 自动评分代替人工听审 | 机器检查不产生人类身份或自然度判断 |

代价是额外的表现任务持久化、证据索引和人工审听工时。收益是缺货可恢复、绑定可追溯、发布可核验，且语音故障不改变世界事实。

## 4. 影响与回退

影响范围覆盖 `contracts/schemas/`、相关 IPC 契约、`engine/application/voice_*`、`speech_unit.py`、`engine/infrastructure/audio/`、绑定 repository/resolver、后续数据库迁移及 App 的任务/听审/说话者状态。既有硬过滤、确定性排序、场景选角约束和 RESERVED→ACTIVE 耐久屏障继续作为基础。

003 迁移不改写；证据和任务表通过新的前向迁移加入。历史绑定缺少证据时标记为待补验，不自动删除、不自动重铸，也不凭“以前播过”取得新合成资格。历史 take 的读取与新增正式合成分别判定。

停用 Foundry 只停止新供给工作，既有合格绑定继续运行。缺少合格绑定时使用 D6 的回退链。回滚版本若不能理解新增证据要求，只进入禁用新合成的受限模式，不能以旧规则继续生成。

provider 已发布资产、人工评审记录与历史 take 不做自动降级迁移。数据恢复依据迁移前备份和兼容性核验；应用回滚不等于删除新增数据。运行开关、失败重试与任务恢复均不触发自动服务升级、模型切换或重新发布。

## 5. 实现依赖与交付边界

| 交付层 | 产物与责任 | 前置条件 |
|:---|:---|:---|
| A 契约与反例 | AGT-ARB：请求、状态、证据范围、错误和恢复协议；provider recorded/fake 响应 | 本 ADR 与现有产品契约 |
| B 持久化与编排 | AGT-DATA / AGT-VOICE：前向迁移、幂等任务、端口、预览与完整发布链 | A |
| C 生产绑定与 UI | AGT-VOICE / AGT-MAC：逐说话者 resolver、严格渲染、听审入口、字幕降级 | A、B；可先使用 fake 验证 |
| D 上游链路准入 | SpeechRail：匹配的证据消费、冷态严格合成、恢复和终态契约 | 与 A–C 独立推进；真实联调前成立 |
| E 首批内容 | 旁白与 3–5 个主要人物的参考确认、复验、人工听审和发布 | B–D 完整闭环 |
| F 场景预热与启用 | 有界调度、重启恢复、逐身份预检、旧配置迁移 | C–E 及第 6 节验收 |

首批内容生产依赖完整发布链，不排在发布实现之前。跨仓只消费版本化 HTTP/WebSocket 契约，不共享代码、虚拟环境或本地路径。上游 App 的 F4/F7/C1 等问题在该 App 承担实际听审或发布入口时成为对应链路前置，不无差别阻塞本仓离线契约开发。

验收命令继续由受保护门禁档案管理。仅增加产品 schema 不自动刷新 registry；门禁档案本身变化时，按 HACF 的架构授权与 registry 流程处理。

## 6. 验收事实

下列事实共同构成生产准入标准；本表不表示这些验证已经执行。

| 编号 | 可判定的验收事实 |
|:---|:---|
| V01 身份分层 | legacy 或缺失 voice pin 的声音不能进入正式绑定；带 pin 但缺合格证据的声音同样不能正式合成 |
| V02 证据范围 | 同一 voice 在正确执行范围通过；错误模型、variant、locale、处理指纹或策略版本在首块音频前拒绝 |
| V03 真实听审 | 机器 pass 不产生人工 accepted；人工记录绑定实际听过的参考与复验音频；重生成音频需要重新确认 |
| V04 冷态闭环 | 冷 worker 可直接执行严格准备与合成，无须先宽松试听；身份漂移拒绝且无音频输出 |
| V05 缺货交付 | 新角色无音色时 Commit 保留、字幕可读、供给状态可见；没有主角声线冒充或无限自动铸造 |
| V06 并发与恢复 | 同 scope 并发只有一个绑定胜者；同键重放不重复资产；部分发布成功和重启后仍恢复原任务 |
| V07 生命周期 | failed、cancelled、deprecated、revoked 的动作各自有效；迟到结果不越过取消或覆盖新 scope 修订 |
| V08 历史连续性 | 显式换声仅影响未来边界；原 take 的引用不变；世界线分叉不继承未来绑定 |
| V09 授权隔离 | 隐藏身份与未来剧情不进入请求、提示词、试听、日志或元数据；schema 与语义授权分别有反例 |
| V10 数据恢复 | runtime 索引清空后，从持久任务和 provider 恢复；表现更新不推进世界 revision；旧绑定缺证据不被静默放行 |
| V11 严格回退 | 停用供给或回滚应用不绕过验收；撤销音色不能借缓存路径规避明确的禁播策略 |
| V12 真实体验 | 首批人物经过人类听审；正式模型下的跨文本身份、自然度、同场区分度及互动资源竞争有记录 |

fake 和契约测试证明状态迁移、授权、幂等与拒绝行为，不证明真实听感。真实音频验收分别记录模型/服务版本、样本、测量日期和人工结论；没有对应记录的项保持未验收。
