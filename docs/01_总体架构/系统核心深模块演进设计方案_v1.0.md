# 系统核心深模块演进设计方案 (v1.0)
## —— 基于 WorldSession 响应式流与 ContextCompiler 铁壁授权

> **状态**：前期准备与系统实现架构深化方案基线  
> **设计目标**：落实 Deep Modules 理论，在 macOS 客户端与 Python 引擎端构筑高杠杆、高内聚的核心接缝  
> **核心哲学**：Small Interfaces · Deep Implementations · High Leverage · Pure Locality  

---

## 1. 现状痛点与深化动因 (Context & Deepening Needs)

在 Phase 0 契约冻结后，代码库具备了坚固的分层隔离与 27 个 JSON Schemas 规范。然而，在现有实现和接下来的 Phase 1 / Phase 2 演进中，存在两个极易退化为“浅模块”的风险点：

1. **macOS 宿主端的“通信浅编排”**：
   - 目前 `AppState.swift` 直接引用了 `EngineProcessManager`、`EngineIPCClient` 与动态信封结构。UI 层需要关心进程是否已启动、Socket 路径、握手心跳和信封解码。
   - **痛点**：若后续引入流式音频（Audio Streaming Chunk）、断线重连或长事务重试，`AppState` 将被网络与系统运维细节淹没，破坏 UI 状态的**局部性 (Locality)**。
2. **引擎编排层的“多路检索胶水”**：
   - 按照叙事引擎设计，上下文构建需要执行：角色视界授权过滤、结构化图谱关系检索、向量相似度召回、全文检索、Rank Fusion 排序以及 Token 动态预算裁剪。
   - **痛点**：若在 `SessionOrchestrator` 中按面向过程的方式串联这 6 个步骤，不仅导致模块过于散碎，还极易在多模块调用接缝中发生秘密信息泄漏（违反核心不变量 6：零知识越界）。

为此，本方案确立两大核心系统深模块：**`WorldSession` (宿主端响应式叙事流)** 与 **`ContextCompiler` (铁壁语义授权编译器)**。

---

## 2. 模块一：`WorldSession` 宿主端深模块设计 (Swift 6)

### 2.1 模块定位与杠杆 (The Seam & Leverage)
`WorldSession` 是 SwiftUI 视图层与同机 Python 引擎之间的物理接缝。
对外，它只提供一个极为简单、纯净的接口；对内，它将**进程监督、IPC 恢复、NDJSON 解析与多事件聚合**全部深度封装。

```text
┌────────────────────────────────────────────────────────┐
│               SwiftUI 视图层 (ContentView)              │
└───────────────────────────┬────────────────────────────┘
                            │ Interface (极简接口):
                            │ worldSession.sendAdvice("提醒克莱恩防备变异")
                            ▼
┌────────────────────────────────────────────────────────┐
│               WorldSession 深模块接缝                  │
│  ┌──────────────────────────────────────────────────┐  │
│  │ 1. 进程监督器: 异常退出自动拉起与状态机维护      │  │
│  │ 2. UDS 连接池: 双向流通信、指数退避断线重连      │  │
│  │ 3. 强类型折叠: 将底层 10+ 类 NDJSON 转换为聚合模型│  │
│  │ 4. 响应式流: 连续产出文字叙事、情绪与音频分片   │  │
│  └──────────────────────────────────────────────────┘  │
└───────────────────────────┬────────────────────────────┘
                            │ 仅向下流式抛出
                            ▼
┌────────────────────────────────────────────────────────┐
│               AsyncStream<NarrativeTurn>               │
│         (包含完整剧情演出、状态变更增量与对齐音频)      │
└────────────────────────────────────────────────────────┘
```

### 2.2 接口契约定义 (The Interface)
```swift
import Foundation

/// 统一的叙事回合响应式事件
public struct NarrativeTurn: Sendable {
    public let turnId: String
    public let role: String
    public let narrativeText: String
    public let isFinal: Bool
    public let stateDelta: StateDeltaDTO?
    public let audioChunk: Data?
}

/// 宿主端唯一的深模块协议
public protocol WorldSession: Sendable {
    /// 观察当前会话状态（空闲、思考中、演播中、故障重连中）
    var sessionStatus: AsyncStream<SessionStatus> { get }
    
    /// 发送玩家建议，开启响应式叙事流
    func sendAdvice(_ adviceText: String) async throws -> AsyncStream<NarrativeTurn>
    
    /// 主动终止并释放底层所有连接与引擎资源
    func close() async
}
```

### 2.3 收益与删除测试 (Leverage & Deletion Test)
- **Deletion Test**：删除 `AppState` 中的 `startEngine()`、`connect()`、`performHandshake()` 及信封派发逻辑，将它们封装到 `WorldSession` 之后。复杂度没有外溢，反而在单一接缝内部完全闭合。
- **Testability**：在进行 UI 自动化或交互测试时，只需编写一个几行代码的 `MockWorldSession`，提供固定的 `NarrativeTurn` 模拟流，SwiftUI 测试不再受 Python 引擎启停和 IPC 延迟影响，执行时间由秒级压缩至毫秒级。

## 3. 模块二：`ContextCompiler` 铁壁语义授权深模块设计 (Python 3.14)

### 3.1 模块定位与硬授权隔离 (Invariant 6 & 7)
`ContextCompiler` 位于应用层（`engine/application/`），是角色推理与真实世界数据之间的坚固防腐层。
它贯彻：**“语义授权先行，物理杜绝越界”**。

```text
┌────────────────────────────────────────────────────────┐
│               Session Orchestrator 会话编排器          │
└───────────────────────────┬────────────────────────────┘
                            │ Interface (极简接口):
                            │ compiler.compile(character_id, world_time, obs)
                            ▼
┌────────────────────────────────────────────────────────┐
│             ContextCompiler 铁壁深模块                 │
│  ┌──────────────────────────────────────────────────┐  │
│  │ 1. 语义硬授权门禁: 物理剔除角色无权获知的秘密   │  │
│  │ 2. 多模型混合召回: 检索 canon.db / retrieval.db   │  │
│  │ 3. Rank Fusion: 融合图谱拓扑权重与语义相似度    │  │
│  │ 4. 动态 Token 预算装配: 基于模型窗口自动最优裁切 │  │
│  └──────────────────────────────────────────────────┘  │
└───────────────────────────┬────────────────────────────┘
                            │ 仅产出符合边界的
                            ▼
┌────────────────────────────────────────────────────────┐
│               ContextPacket (上下文数据包)             │
│            100% 杜绝知识泄露 · 格式完全适配大模型      │
└────────────────────────────────────────────────────────┘
```

### 3.3 内部实现算法三道防线 (Internal Pipeline)
1. **第一道防线：基于角色的硬知识隔离 (Hard Masking)**：
   - 查询 `character_knowledge` 登记表，仅提取 `visibility_level <= character.clearance` 的条目；
   - 过滤所有标记为 `is_secret=True` 且角色无直接接触史的 Canon 记录。
2. **第二道防线：图谱与向量混合召回 (Hybrid Candidate Generation)**：
   - 结构化关系检索（以该角色为中心的二阶拓扑邻居）；
   - 向量检索（针对当前观察事件的情境语义召回）；
   - 使用倒数排名融合（Reciprocal Rank Fusion, RRF）合并候选集。
3. **第三道防线：动态预算打包 (Knapsack Packing)**：
   - 按重要度权重由高至低填入 ContextPacket，当总 Token 达到上限时平滑截断，确保模型 Prompt 永不溢出。

## 4. 与后续里程碑的演进接合 (Milestone Alignment)

| 里程碑 | 目标工作 | 深模块落地方式 |
|:---|:---|:---|
| **Phase 1 (M1)** | 本地引擎打包与启动拓扑 | 验证 `WorldSession` 的子进程拉起与 UDS 通信稳定性。 |
| **Phase 1 (M2)** | SQLite 多模型四库内核落地 | `ContextCompiler` 内部对接 `canon.db` 与 `retrieval.db` 实体数据。 |
| **Phase 2 (M3)** | 确定性 Outcome Resolver 落地 | Resolver 将提交后的事件推送给 `WorldSession` 的响应式流。 |
| **Phase 2 (M4)** | AgentScope 2.0.8 接入 | AgentScope 仅接收 `ContextCompiler` 输出的 `ContextPacket`，绝不直接查询数据库。 |

## 5. 方案总结

通过在宿主端沉淀 **`WorldSession`**，在引擎端沉淀 **`ContextCompiler`**：
1. 我们消除了散落的胶水代码，将复杂的网络生命周期与复杂的授权召回算法深锁在两处坚固的接缝之后；
2. 保证了在接下来的 M1-M6 大规模开发中，任何开发者或专精 Agent 均只能通过小接口与核心系统交互，最大化保障了系统的长期健壮性与可维护性。
