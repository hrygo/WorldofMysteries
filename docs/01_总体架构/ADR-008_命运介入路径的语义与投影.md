# ADR-008：命运介入路径的语义与投影

> **状态**：待裁决（提案；供人类架构师与 AGT-ARB 评审）  
> **日期**：2026-10-03  
> **职责**：人类架构师负责架构裁决；AGT-ARB 维护决策与契约边界  
> **作用范围**：PRD §20 Story Book 的第五段、`storybook.schema.json`、`storybook_projection.py` 的读模型边界  
> **前置文档**：[ADR-002](ADR-002_数据架构.md)、[PRD 产品基线 §20](../00_产品/诡秘世界_PRD_产品基线_v1.0.md)、[ADR-006](ADR-006_叙事块的说话人语义.md)  
> **语态约定**：第 2–4 节以终态事实语态定义候选方案；第 1 节记录当前证据，第 5 节记录决策状态。本 ADR **不裁决**，只把选项与各自代价摆开。

## 1. 背景与证据边界

PRD §20 列出 Story Book 的十项内容，其中第五项为「命运介入路径」，而 §20.3 的标题写作「命运记录」，正文只给了一段示意：

```text
调查尸体 → 隐藏身份 → 相信陌生人 → 拒绝仪式 → 保护受害者 → 开放结局
```

核验时间 2026-10-03，运行环境 macOS 26+ / arm64。以下均为源码核实，非文档转述。

**已落地**：前四段（已发现秘密、关键人物、关系变化、世界影响）由 `engine/application/storybook_projection.py` 的 `project_story_book` 装配，数据源是 `StoryBookArtifacts` 携带的四组 Episode 已提交记录，全部读自已提交快照。契约侧 `storybook.schema.json` 的 `additionalProperties: false`，而这四段不在 `required` 之内——它们是**加性可选**，旧 bundle 缺失时得到空段而非报错（见 `project_story_book` 文档字符串）。

**未落地**：`storybook.schema.json` 的 15 个属性中没有任何字段承载第五段；PRD §20.3 的示意没有任何实现。

本节只确认「是什么」与「不是什么」，不推断「应该是什么」。

## 2. 问题陈述

第五段要投影的**是什么**，当前无法从代码或 PRD 唯一确定。三个候选数据源各自携带一条硬约束，彼此不相容：

| 候选源 | 表 / 位置 | 提交绑定 | 与不变量 4 的关系 |
|:---|:---|:---|:---|
| 玩家建议原文 | `turn_advice_interpretations`（迁移 009） | **无** `committed_world_revision`；注释明写「never advances world_meta or creates Domain events」 | 直接冲突：建议 ≠ 命令，投影它会把「玩家想让他做的事」写成「他做的事」 |
| 叙事编排意图 | `beat_plans.npc_intents` / `dramatic_goal` / `intervention_required`（迁移 012） | **无** `domain_commits` 外键；由 post-commit 表达式发布，是编排产物 | 不直接冲突，但「意图」不是「已发生」 |
| 状态变化事件 | `episode_character_events` / `episode_relationship_events` / `episode_knowledge_changes` / `episode_world_events`（迁移 011） | **有** `committed_world_revision REFERENCES domain_commits(revision) DEFERRABLE INITIALLY DEFERRED` | 相容，但这四组已经是现有四段；它们是结果快照，不是行动链 |

PRD §20.3 的示意（「调查尸体」→「保护受害者」）读起来像**主角实际做了什么**，而非状态差分；但代码里没有一张表以「行动」为粒度记录已提交事实。`narrative_blocks` 绑定 `domain_commits(revision)`，但它记的是说出来的话，不是做过的事。

这就是需要人类裁决的全部：**「命运介入路径」到底指玩家介入的轨迹，还是主角的行动轨迹。**

## 3. 为什么不能由实现侧自行选定

三条既有约束把这件事推给人类架构师，绕不过去：

1. **不变量 4（Advice ≠ Command）**：选玩家建议原文是最省事的实现，但它把玩家的意图写成角色的行为。这是产品语义的改变，不是投影口径的选择。
2. **SB-18 钉死的读模型边界**：`scripts/check_architecture_fitness.py` 的 `check_storybook_reading_path_is_model_free` 断言阅读路径零 model / network import。第五段不能靠「让模型总结已提交事实」来实现——那正是 PRD §20.1 禁止的「结束后让模型重写一篇差不多的小说」。
3. **命名本身未统一**：§20 总清单写「命运介入路径」，§20.3 标题写「命运记录」。两者指向不同的读者心智（玩家的介入 vs 角色的轨迹），未裁决就无法确定契约字段该叫什么。

## 4. 候选方案

以下四个方案均**满足**第 3 节的三条约束，差别在读出的内容与代价。

### 4.1 方案 A：主角行动轨迹（自 `narrative_blocks` 派生）

以已提交的叙事分段为源，按章节顺序抽出主角（或各在场角色）的行为陈述，构成一条轨迹。

- 优点：满足 §20.3 示意的读感；源已绑定 `domain_commits`；零新增迁移。
- 代价：分段记的是**说的话**，从中判定「做了什么」需要抽取判断，而这个判断若交给模型就撞上 §3.2，若交给规则则抽取质量受限。轨迹会读成「他说他调查了尸体」而非「他调查了尸体」。
- 风险：低。契约加一个可选数组字段，与现有四段同构。

### 4.2 方案 B：状态差分链（复用 `episode_*` 已提交记录）

把四组已提交事件按 `committed_world_revision` 排序，投影成一条「世界如何因这些角色而改变」的链。

- 优点：全部字段已是权威事实，无需任何推断；与现有四段共用同一份 `StoryBookArtifacts`，实现成本最低。
- 代价：得到的是**结果**不是**行动**。「隐藏身份」若恰好是某条 `character_events`，读感接近示意；但多数条目会读成「某秘密被发现」而非「他选择隐藏身份」。与 `world_impacts` 段高度重叠，可能只是换个排序。
- 风险：低，但产品价值存疑。

### 4.3 方案 C：玩家介入轨迹（自 `turn_advice_interpretations` 派生）

投影玩家每回合给出的建议，并**明确标注这些是建议而非既成事实**。

- 优点：直接对应「命运介入路径」这个 PRD 总清单用词；数据已存在（迁移 009）。
- 代价：必须解决不变量 4——要么在契约层显式区分「玩家介入」与「已发生」（读者不会混淆），要么违反不变量 4。这使 Story Book 出现两种性质截然不同的段落，需要 UI 层也区分呈现。
- 风险：**高**。触及不变量 4 的解释边界，须由人类架构师明写口径。

### 4.4 方案 D：新增「已提交行动」记录（需前向迁移）

在回合提交时持久化裁决器判定的行动条目（谁、做了什么、依据哪个 intent），第五段从该表投影。

- 优点：唯一能让「行动」成为一等已提交事实的方案，粒度与示意一致；不依赖任何推断。
- 代价：新增迁移落在高风险面（需仲裁扩权）；裁决器当前是否产出可持久化的行动判定需另行核实——本 ADR **未**核实裁决器的输出形状，若裁决器不产出该结构，方案 D 的成本会显著高于上表。
- 风险：高。

### 4.5 对照

| | 读出的内容 | 新增迁移 | 触及不变量 4 | 实现成本 |
|:---|:---|:---|:---|:---|
| A 主角行动轨迹 | 说的话所指向的行为 | 无 | 否 | 中（需抽取规则） |
| B 状态差分链 | 已提交的结果 | 无 | 否 | 低 |
| C 玩家介入轨迹 | 玩家的建议 | 无 | **是** | 低 |
| D 已提交行动记录 | 裁决器判定的行动 | **有** | 否 | 高（需先核实裁决器输出） |

## 5. 迁移、兼容与回退

无论选哪个方案，契约变更都是加性的：`storybook.schema.json` 的 `additionalProperties: false` 意味着新增字段必须显式声明，而现有四段的先例证明可选段可以安全加入（旧 bundle 缺失时投影给空段，不报错）。因此回退代价低——移除字段即可，既有 bundle 无需迁移。

方案 D 例外：它需要前向迁移，回退涉及迁移策略，须按 ADR-002 的前向迁移纪律单独立项。

## 6. 测试策略

投影层新增测试须与现有四段同构：断言第五段在 bundle 缺失该数据时给出空段而非报错，并断言其内容全部来自已提交源。第 3 节的三条约束各自需要一条守卫：

- 不变量 4：若选方案 C，须有一条测试断言玩家建议在书里被标注为建议；
- §20.1 读模型边界：`check_storybook_reading_path_is_model_free` 已覆盖全模块，无需新增；
- 提交绑定：若选方案 D，须断言新表同样带 `committed_world_revision` 外键。

## 7. 与既有决策的关系

- **不变量 4**：方案 C 直接触及，其余方案不相交。
- **不变量 5**（AI 仅产出 Proposal）：方案 D 的「行动」必须是裁决器判定结果，不是模型提议——这是它区别于 `beat_plans.npc_intents` 的关键。
- **不变量 9 / PRD §20.1**：由 SB-18 的 `check_storybook_reading_path_is_model_free` 强制，四个方案均不违反。
- **ADR-006 D1**（旁白身份由可信源写入）：若最终选择涉及按说话人分层，需与该条一致。

## 8. 决策状态

**待裁决**。需人类架构师裁定：

1. 「命运介入路径 / 命运记录」指的是**玩家介入的轨迹**还是**主角的行动轨迹**（这一项先决，其余选项依赖它）；
2. §20 总清单与 §20.3 标题的命名不一致以哪个为准，契约字段据此命名；
3. 在 4.1–4.4 中选哪一个；若选 D，需另行核实裁决器是否产出可持久化的行动判定，并按 ADR-002 单独立项。

未裁决前，**实现保持现状**：第五段不实现，`storybook.schema.json` 不加该字段。任何在裁决前写入第五段的实现都等于替架构师做了上面第 1 项决定。

本 ADR 不授权任何绕过上述裁决的改动。
